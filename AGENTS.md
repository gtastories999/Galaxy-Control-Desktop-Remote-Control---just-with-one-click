# Project instructions
Communicate with the user in German. Author product UI, source comments, documentation and commits in English.
Keep support attended and visible. Never add hidden access, startup persistence or unattended reconnection.
Use each operator's own Supabase project. Never include real project URLs, keys, user tokens or passwords in public builds or source. Keep connection.local.json ignored.
Never distribute secret or service-role keys; use only a publishable key plus end-user Supabase Auth tokens.
Verify the PostgreSQL permissions and directory schema, Supabase HTTP client, direct-only browser transport, actual Windows WebView2 bridge and Windows publish before release.
Never add TURN or screen/input forwarding to Supabase. Only directory metadata, SDP and ICE may be stored or exchanged there.

Each distributor or fork must register its own Supabase Management API OAuth application and deploy its own account-exchange backend. Never default forks or public generic builds to the original author's OAuth application or broker. Keep setup-provider.json empty in generic builds and setup-provider.local.json ignored. OAuth client secrets stay exclusively in each developer's server environment; only the public broker URL may enter that developer's configured build.

Galaxy is the umbrella brand for all Galaxy projects. Use Gradient Yellow Gold as the brand accent in every Galaxy logo and button, including onboarding, authentication, setup, hover and focus states. Use neutral supporting surfaces and text; do not introduce green branding. Preserve this rule when adding or updating Galaxy interfaces and assets.

Use the existing gold 3D star-and-orbit logo in src/GalaxyControl/Assets/galaxy-logo.png across login and setup. Do not create a replacement logo or alternate identity.
